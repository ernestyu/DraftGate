# 为什么 AI 写作需要显式状态

这篇文章要回答一个很具体的问题：AI 已经能够读取长上下文，也能理解“现在在改结构”“下一步再润色”这样的指令，为什么复杂长文写作仍然需要把工作流状态单独记录在模型之外？

核心判断是：内容判断和流程事实属于两类不同的问题。模型适合处理“这个论点是否成立”“这一段是否清楚”这类需要语义判断的任务，但“当前已经完成 G3”“下一步只能执行 G4”“这次修改必须基于哪一个文章版本”属于确定性状态。把这些事实只留在对话上下文里，就等于要求一个概率模型同时承担编辑判断和状态机职责；把它们写进 Git 与结构化 state 后，模型仍然负责判断，流程事实则由外部系统记录和验证。

本文只讨论这种职责分离为什么有用，不主张显式状态本身能提高文章质量。它解决的是流程是否可检查、能否恢复、是否会跳步的问题；具体内容是否正确，仍然需要人和模型在各个写作阶段判断。
